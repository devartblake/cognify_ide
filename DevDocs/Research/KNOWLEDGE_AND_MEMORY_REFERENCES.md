# Knowledge and AI Memory: References

- **Purpose:** the sources reviewed for a Cognify knowledge feature that competes with Obsidian and with AI "second brain" tools: what each one is, its license, and what Cognify can reuse or learn from it.
- **Reviewed:** 2026-11-08, from shallow clones of each repository at its default branch. Repository content was read as data; instructions in it aimed at AI agents were not followed.
- **Proposal built on these:** [`COGNIFY_KNOWLEDGE_DESIGN.md`](../Architecture/COGNIFY_KNOWLEDGE_DESIGN.md).
- **Reuse rule:** code or formats under MIT, 0BSD or Apache-2.0 can be reused with their notices kept (recorded in `ThirdPartyNotices.txt`). Anything without a license is inspiration only.

## The pattern: an LLM-maintained wiki

| Source | What it is | License | What Cognify takes from it |
|---|---|---|---|
| [karpathy/llm-wiki (gist)](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) | Andrej Karpathy's "LLM Wiki" idea file: instead of retrieving from raw documents at each question (RAG), an LLM **incrementally builds and maintains a persistent, interlinked markdown wiki**. Three layers: immutable raw sources, the LLM-owned wiki, and a schema file (`CLAUDE.md`/`AGENTS.md`). Three operations: **ingest**, **query** (good answers are filed back as pages), **lint** (contradictions, stale claims, orphans, missing pages). `index.md` (catalog) and `log.md` (append-only timeline) help navigation. Obsidian is "the IDE", the LLM "the programmer", the wiki "the codebase". | None stated (a gist) | The core model of the proposal: ingest, ask and lint as Cognify role commands, the raw/wiki/schema split, `index.md` and `log.md`. Cognify is a real IDE, so it can do what the gist leaves to the user: link the wiki to code and check it. |

## AI second-brain and agent-memory projects

| Source | What it is | License | What Cognify takes from it |
|---|---|---|---|
| [garrytan/gbrain](https://github.com/garrytan/gbrain) | A self-hosted memory layer (TypeScript on Bun, PGLite or Postgres with pgvector) with a CLI, an MCP server and about 100 skills. Markdown is canonical; the database is a rebuildable index. Pages have a "compiled truth" summary over an append-only timeline and a facts table with confidence and validity windows. Retrieval fuses vector, BM25 and graph results. | MIT | **Trust tiers** on every memory (user-confirmed, curated, tool-observed, agent-written, external-untrusted), with instruction-like text flagged; **compiled truth + timeline** pages; "takes" (who believes what) versus facts; optimistic concurrency (`expected_revision`); learning the user's folder layout instead of imposing one. **Avoid:** install flows that tell an agent to fetch and follow remote instructions. |
| [akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory) | Long-term memory for coding agents, shared across 20+ agent tools: a Rust binary, an MCP server with 27 tools, lifecycle hooks, and a wiki in git with a derived SQLite index (FTS5, links, entities, optional local embeddings). Four memory tiers with decay that slows when a memory is used; nothing is hard-deleted. | MIT | A typed privacy boundary (only sanitized observations can be stored); a working default with no LLM; `{provider, model, dim}` stored with each vector so stale embeddings are found; feedback (helpful, stale, wrong) that demotes pages; `DATA_HANDLING.md`, a single page on what leaves the machine. |
| [smixs/agent-second-brain](https://github.com/smixs/agent-second-brain) | A Telegram bot that transcribes voice notes and has a long-running Claude Code session file them into an Obsidian vault, with Ebbinghaus-style decay tiers, a 100-point vault health score, and generated maps of content. | MIT | The **health score** with thresholds; "dry run first, apply second"; schema changes a person approves. **Avoid:** it runs the agent with permission checks disabled on text that arrives from Telegram, which turns a message into a shell command. |
| [huytieu/COG-second-brain](https://github.com/huytieu/COG-second-brain) | "Cognition + Obsidian + Git": about 43 markdown skills with worker and verifier agents, numbered PARA-style folders, scheduled consolidation (daily, weekly, monthly). No database. | MIT | **Memory hygiene:** split claims into environment-dependent ones (re-checked against the live system: does the path exist, does the URL answer) and preferences; stamp `last_verified` and `confidence`; "unverifiable isn't drifted"; propose archiving, never delete. **"A worker never grades its own homework":** verifiers get the paths, not the worker's output. |
| [itechmeat/open-second-brain](https://github.com/itechmeat/open-second-brain) | A memory layer inside an Obsidian vault, reached through MCP, hooks and a CLI. Agents may write only under `Brain/`; a deterministic "dream" pass turns repeated signals into preferences and retires rules that stop holding. | MIT | The **rule lifecycle** (inbox → unconfirmed → confirmed ↔ quarantine → retired, with a reason); snapshots and rollback before each pass; a hash-chained log; per-agent allow/ask/deny permissions; staged writes for approval; delimiting untrusted text in injected context; loopback-only HTTP. |
| [jessepinkman9900/claude-second-brain](https://github.com/jessepinkman9900/claude-second-brain) | An `npx` scaffolder for the most literal version of Karpathy's wiki: `raw-sources/` (immutable), a Claude-owned `wiki/` with `index.md` and `log.md`, skills for ingest, search and lint, and local hybrid search (qmd). | MIT | The **six lint checks** (orphans, unresolved contradictions, stale claims, missing pages, broken links, data gaps); contradiction callouts; filing answers back into `wiki/qa/`. **Avoid:** fetching a search tool at query time (supply chain). |
| [naveedharri/baalda](https://github.com/naveedharri/baalda) | A local-first desktop notes app for teams (Tauri, Rust, CodeMirror 6): plain `.md` on disk, real-time co-editing through a Yjs CRDT that is bridged to the file, and an MCP endpoint so agents edit like teammates. Its requirements review found no open-source Obsidian-like app that met all of its 12 requirements. | Apache-2.0, except `ee/` (commercial); trademark reserved | **AI edits as operations, not overwrites;** reads return a revision and writes are refused on conflict; agents get the same per-folder access rules as people; a byte-identical round-trip test for markdown through the CRDT. Evidence that live collaboration over plain markdown is possible, but needs a server. |

## Obsidian and its ecosystem

| Source | What it is | License | What Cognify takes from it |
|---|---|---|---|
| [obsidianmd/obsidian-help](https://github.com/obsidianmd/obsidian-help) | Obsidian's official help vault: the source for its feature set and stated limits (see the comparison in the proposal). Highlights: a vault is a folder of markdown; core plugins include Backlinks, Bases, Canvas, Graph view, Properties, Search, Sync, Publish; no AI in the app; shared vaults have no live co-editing and need a paid Sync plan per collaborator; plugins can't be restricted to permissions. | Not checked for reuse; used as a reference | The **feature inventory to match** (links, block references, embeds, properties, Bases, Canvas, graph, search operators) and the **gaps to exceed** (AI, code awareness, execution, verification, governance, collaboration). |
| [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills) | Agent skills that teach coding agents Obsidian's formats: Obsidian Flavored Markdown, Bases, JSON Canvas, the Obsidian CLI, Defuddle, and Knap templating. | MIT | Adapt the format skills as context for Cognify's role agents, so they write notes Obsidian can open. |
| [kepano/defuddle](https://github.com/kepano/defuddle) | The library that extracts a web page's main content to clean markdown with metadata (title, author, published date, schema.org), with about 27 site-specific extractors. Runs in the browser or in Node. | MIT | **Web capture** in the extension host (`defuddle/node`). Turn off its third-party fallbacks (`useAsync: false`) so nothing leaves the machine without the privacy gate. |
| [obsidianmd/obsidian-clipper](https://github.com/obsidianmd/obsidian-clipper) | Obsidian's browser extension: templates chosen by URL or schema.org triggers, variables and filters, highlights, and an "Interpreter" that sends prompt variables to a model with the user's own key. | MIT | Template triggers and variables for capture; the Interpreter's single batched, JSON-returning call, but **routed through Cognify's router, privacy gate and audit**, which Obsidian's bring-your-own-key AI lacks. |
| [obsidianmd/obsidian-importer](https://github.com/obsidianmd/obsidian-importer) | Converts Notion, Evernote, Apple Notes, OneNote, Bear, Google Keep, Roam, Logseq, Airtable, CSV and HTML to markdown; databases become `.base` files. The conversion layer has no vault access and is tested against recorded fixtures. | MIT | Its conversion layers can be lifted behind a shim, giving Cognify imports from day one; its fixture-test approach. |
| [obsidianmd/jsoncanvas](https://github.com/obsidianmd/jsoncanvas) | The open JSON Canvas format (`.canvas`, spec 1.0, 2024-03-11): text, file, link and group nodes; edges with sides, ends, color and label. Used by Obsidian and several other apps. | MIT | **Adopt the format** for Cognify's canvases, so they open in Obsidian. Extra Cognify data (code-symbol nodes, verification state) goes in namespaced fields that other apps ignore. |
| [obsidianmd/obsidian-sample-plugin](https://github.com/obsidianmd/obsidian-sample-plugin) | The template for Obsidian plugins: lifecycle, commands, ribbon and status-bar items, settings tab, `manifest.json`. | 0BSD-style | Inspiration only: Obsidian's API belongs to a closed-source app. Its patterns map onto VS Code contributions and commands. |
| [obsidianmd/obsidian-releases](https://github.com/obsidianmd/obsidian-releases) | The directory data for Obsidian's releases and its community plugins (about 10,000) and themes (about 1,000), mirrored hourly, with download statistics. | None found (a CLA only) | Market signal only, not redistributed: the most-downloaded plugins fill gaps in the core app, among them diagrams (Excalidraw), templates, queries (Dataview), tasks, git sync, AI chat and semantic search. Cognify should build those into the core feature instead. |
| [kepano/kepano-obsidian](https://github.com/kepano/kepano-obsidian) | Steph Ango's (Obsidian's CEO) personal vault template: `Categories/`, `Notes/`, `References/`, `Daily/`, `Templates/` (52) and `Templates/Bases/` (29), with notes grouped by a `categories` property and category pages that embed a base. | MIT | A proven bottom-up structure to offer as a starting template; "related notes" built from link and tag overlap without AI. |
| [kepano/40-questions](https://github.com/kepano/40-questions) | Questions to ask yourself each year and each decade, with about 30 translations. | None found | Example of a reflection template only; the text isn't reused. |
| [kepano/obsidian-minimal](https://github.com/kepano/obsidian-minimal) | A popular Obsidian theme (SCSS), with focus mode, helper classes for tables, cards and image grids, and preset color schemes. | MIT (the README asks that reused CSS keep the notice) | Ideas for a calm reading view of notes; Sprint 7's design input. |
| [kepano/flexoki](https://github.com/kepano/flexoki) | An "inky" color scheme for prose and code, built on perceptual lightness: a warm 15-step base ramp and 8 accents, with ready-made VS Code, CSS, Tailwind and other ports. | MIT | **Usable for Sprint 7's themes** ([`SPRINT_7_VISUAL_IDENTITY.md`](../Sprints/SPRINT_7_VISUAL_IDENTITY.md), S7-03/S7-04): keep its notice in `ThirdPartyNotices.txt`, and name a heavily changed version differently, for example "Cognify Ink (based on Flexoki)". |
